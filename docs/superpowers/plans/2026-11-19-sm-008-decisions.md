**What this means for part 3**
- The first choice works without an admin prompt: one Interactive wake task per queued post in `\SocialMediaManager\`. Its limit is that it runs only while the owner is signed in; after a full sign-out, the post goes to Missed.
- A standing task whose times the app rewrites is **not** possible (denied).
- **Waking from sleep is still open.** With wake timers set to "important only" (plugged in) and "off" (battery), Windows may not let the task wake the laptop. The sleep test (`-Sleep`) runs in the bring-up session with the owner:
  1. First as the settings are now.
  2. If it does not wake, ask the owner whether to set **Allow wake timers = Enable** for plugged in (Control Panel → Power Options → Change plan settings → Advanced → Sleep → Allow wake timers), and for battery too if they want posts while unplugged. Then run it again.
- Record the result below.

**Setting changed (owner's choice, 21 Nov 2026):** "Allow wake timers" = **Enable when plugged in**, battery stays **Off** (so the laptop never wakes in a bag). Made with `powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP RTCWAKE 1` + `powercfg /setactive SCHEME_CURRENT` from a normal window: **no admin prompt needed**. To undo: the same with `2` (important only). The setting belongs to the current power plan; another plan, or a large Windows update, may bring back "important only".

**Decision for part 3:** one Interactive `WakeToRun` task per queued post in `\SocialMediaManager\`, made and removed by the app without an admin prompt. It wakes the laptop from sleep when plugged in, and runs while the owner is signed in (a locked screen counts). Not covered: shut down, signed out, or asleep on battery; those posts go to Missed. Part 3 should check the wake-timer setting (`powercfg /query … RTCWAKE`, AC value 1) in `smm:doctor` and warn on the dashboard if it falls back. Lid closed was not tested.
